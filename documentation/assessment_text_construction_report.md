## 2. Canonical Document Schema

The canonical document is structured with explicit markdown-style section demarcations, designed to maximize self-attention coherence across teacher criteria, student responses, and corrective guidance:

```text
[Mata Pelajaran]: {subject_name}

[Jenjang Kelas]: {class_level}

[Pertanyaan / Soal]:
{question_text}

[Kunci Jawaban / Konsep Kunci]:
{answer_key}

[Rubrik Penilaian]:
- {kriteria_1} (Maks: {points} poin): {deskripsi_1}
- {kriteria_2} (Maks: {points} poin): {deskripsi_2}

[Jawaban Siswa]:
{student_answer}

[Evaluasi & Koreksi Guru]:
{teacher_feedback}

[Skor Guru]: {final_score} / {max_score}
```

## 3. Deterministic Normalization Rules

| Step | Normalization Rule | Implementation Detail | Rationale |
| :--- | :--- | :--- | :--- |
| **1. Unicode Normalization** | **NFKC** (*Compatibility Decomposition followed by Canonical Composition*) | `unicodedata.normalize('NFKC', text)` | Converts full-width characters (e.g. `Ｈｕｋｕｍ` $\to$ `Hukum`), ligature symbols, and weird unicode spaces into standard UTF-8 characters without altering semantic meaning. |
| **2. Linebreak Standard** | **LF (`\n`)** | `re.sub(r'\r\n\|\r', '\n', text)` | Standardizes cross-platform Windows (`\r\n`) and Unix (`\n`) line endings. |
| **3. Paragraph Collapsing** | Max 2 consecutive newlines | `re.sub(r'\n{3,}', '\n\n', text)` | Prevents token wastage from excessive blank lines while preserving paragraph boundaries. |
| **4. Whitespace Trimming** | Per-line & Global Trim | `re.sub(r'[ \t]+$', '', line)` | Eliminates trailing spaces/tabs on individual lines and trims outer boundaries. |
| **5. HTML Entity / Tag Stripping** | Safe Tag Strip + Entity Decode | `html.unescape()` + Regex tag removal | Strips `<p>`, `<b>`, `<span>`, `<br/>` generated by rich text editors while decoding entities (`&lt;` $\to$ `<`, `&gt;` $\to$ `>`). |
| **6. LaTeX & Math Preservation** | **STRICT PRESERVATION** | Backslashes and math constructs (`\frac`, `\sqrt`, `\int`, `^2`, `_2`) are **never stripped**. | Ensures mathematical formulas in Chemistry, Physics, and Math exams remain 100% semantically valid for Transformer embeddings. |
| **7. Rubric JSON Serialization** | Deterministic Key Extraction | Standardized criteria ordering with points and descriptions. | Produces identical string output regardless of dictionary key insertion order. |
| **8. Language Preservation** | **Original Indonesian Educational Text** | No machine translation or language mutation. | Preserves Indonesian curriculum terminology and pedagogical nuances. |

## 4. Privacy & PII Boundary Enforcement

To ensure strict GDPR/educational data privacy compliance:
- **Exclusion Invariant:** The canonical document and the future embedding vector **NEVER** contain:
  - Student Name (e.g. *"Arselio Theo"*)
  - Student Username / Email
  - Student NIS / NISN (e.g. *"09876"*)
  - Device IP Address (e.g. *"10.196.199.15"*)
  - Device Fingerprint / Browser User-Agent
  - Student Database Account ID
- **Verification:** Unit test `test_strict_pii_exclusion` asserts that none of these tokens are present in `canonical_text` or `e5_passage_text`.

## 5. Chunking Strategy & Architectural Decision

### 🎯 Recommendation: **Single Unified Document per Assessment Record (Approach A)**

| Strategy | Token Fit | Context Cohesion | Retrieval Quality | Recommendation |
| :--- | :--- | :--- | :--- | :---: |
| **Approach A: Single Unified Document** | ~250–450 tokens (Fits comfortably within `multilingual-e5-large` 512 context limit) | 🟢 **Optimal**: Keeps Question, Rubric, Student Answer, and Teacher Feedback together in one semantic vector. | 🟢 **Highest**: Vector query directly finds matching question-answer-rubric pairs. | **RECOMMENDED** |
| **Approach B: Multi-Chunk Splitting** | ~100 tokens per chunk | 🔴 **Fragmented**: Separates student error from teacher correction, causing loss of reasoning context. | 🔴 **Degraded**: May retrieve a rubric chunk without knowing why the teacher gave a specific score. | ❌ Rejected |

**Conclusion:** Each `AssessmentHistory` record produces exactly **one** unified canonical document.

## 6. E5 Compatibility: Document vs. Query Distinction

The `intfloat/multilingual-e5-large` model requires explicit asymmetric task prefixes to distinguish documents from queries:

### A. Document Embedding Format (For Knowledge Base Indexing):
```text
passage: [Mata Pelajaran]: Kimia

[Jenjang Kelas]: XI

[Pertanyaan / Soal]:
Jelaskan Hukum Perbandingan Berganda Dalton!

[Kunci Jawaban / Konsep Kunci]:
Bila dua unsur membentuk dua senyawa atau lebih...

[Rubrik Penilaian]:
- Konsep Dasar (Maks: 5 poin): Menyebutkan dua unsur membentuk senyawa
- Perbandingan Massa (Maks: 5 poin): Menjelaskan massa perbandingan bulat sederhana

[Jawaban Siswa]:
Hukum Dalton berbunyi: Jika dua unsur bereaksi membentuk dua atau lebih senyawa...

[Evaluasi & Koreksi Guru]:
Jawaban sangat akurat dan memenuhi semua rubrik Dalton.

[Skor Guru]: 9.5 / 10
```

### B. Query Embedding Format (For Future Runtime Retrieval in Milestone A5):
```text
query: [Mata Pelajaran]: Kimia

[Jenjang Kelas]: XI

[Pertanyaan / Soal]:
Jelaskan Hukum Perbandingan Berganda Dalton!

[Rubrik Penilaian]:
- Konsep Dasar (Maks: 5 poin): Menyebutkan dua unsur membentuk senyawa
- Perbandingan Massa (Maks: 5 poin): Menjelaskan massa perbandingan bulat sederhana

[Jawaban Siswa]:
Dua unsur bergabung membentuk senyawa dengan perbandingan massa tetap.
```

## 7. Deterministic Hashing & Versioning Strategy

- **Hash Algorithm:** Standard **SHA-256** computed over the UTF-8 encoded `canonical_text`.
- **Properties:**
  - **Deterministic:** Identical `AssessmentHistory` payloads always produce the identical 64-character hex hash.
  - **Sensitive to Corrections:** If a teacher edits a score (e.g. $8.0 \to 9.5$) or updates feedback, `content_hash` changes immediately.
  - **Isolated from Surrogate Keys:** Database IDs (`id`, `public_id`), created timestamps, and student account IDs are **excluded** from the hash payload.
  - **Version Coupling:** History $v_1$ and history $v_2$ maintain separate immutable canonical documents and distinct content hashes.
